# Correção de Hook do ECC — 2026-04-21

## Resumo

O Claude Code CLI v2.1.116 no Windows estava falhando em todas as invocações de Hook da ferramenta Bash com:

```
PreToolUse:Bash hook error
Failed with non-blocking status code:
C:\Program Files\Git\bin\bash.exe: C:\Program Files\Git\bin\bash.exe:
cannot execute binary file

PostToolUse:Bash hook error  (mesmo erro acima)
```

Resultado: o `observations.jsonl` parou de ser atualizado após `2026-04-20T23:03:38Z`
(a última entrada era um `parse_error` de um problema anterior de BOM no stdin).

## Causa Raiz

O arquivo `C:\Users\sugig\.claude\settings.local.json` tinha dois defeitos:

### Defeito 1 — BOM UTF-8 + terminações de linha CRLF

O arquivo começava com `EF BB BF` (BOM UTF-8) e usava terminadores de linha `CRLF`.
Este é o comportamento padrão do `ConvertTo-Json | Out-File` do PowerShell, e é
o que `patch_settings_cl_v2_simple.ps1` deixa para trás ao reescrever o arquivo.

```
00000000: efbb bf7b 0d0a 2020 2020 2268 6f6f 6b73  ...{..    "hooks
```

### Defeito 2 — Invocação duplamente envolvida do bash.exe

A string de command reinvocava explicitamente o bash.exe:

```json
"command": "\"C:\\Program Files\\Git\\bin\\bash.exe\" \"C:\\Users\\sugig\\.claude\\skills\\continuous-learning\\hooks\\observe-wrapper.sh\""
```

Quando o Claude Code executa isso no Windows, a divisão de argumentos não preserva
corretamente o token `"C:\Program Files\..."` com aspas. O espaço embutido em
`Program Files` divide o `argv[0]`, e o `bash.exe` acaba sendo passado para
si mesmo como um arquivo de script, produzindo:

```
bash.exe: bash.exe: cannot execute binary file
```

### Formato anterior funcional (para referência)

Antes de `patch_settings_cl_v2_simple.ps1` ser executado, o command era simplesmente:

```json
"command": "C:\\Users\\sugig\\.claude\\skills\\continuous-learning\\hooks\\observe.sh"
```

O Claude Code no Windows detecta `.sh` e o invoca via Git Bash automaticamente — não
é necessário envolver manualmente com `bash.exe`.

## Correção

O arquivo `C:\Users\sugig\.claude\settings.local.json` foi reescrito como UTF-8 (sem BOM), com
terminações de linha LF, com o command apontando diretamente para o wrapper `.sh` e
passando a fase do Hook como um argumento simples:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "command",
            "command": "C:/Users/sugig/.claude/skills/continuous-learning/hooks/observe-wrapper.sh pre"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "command",
            "command": "C:/Users/sugig/.claude/skills/continuous-learning/hooks/observe-wrapper.sh post"
          }
        ]
      }
    ]
  }
}
```

Benefício adicional: o argumento `pre` / `post` agora é roteado para a variável
`HOOK_PHASE` do `observe.sh`, de modo que os eventos são registrados corretamente como `tool_start` vs
`tool_complete` (anteriormente tudo era registrado como `tool_complete`).

## Verificação

Invocação direta do novo formato de command, simulando ambas as fases do Hook:

```bash
# Caminho PostToolUse
echo '{"tool_name":"Bash","tool_input":{"command":"pwd"},"session_id":"post-fix-verify-001","cwd":"...","hook_event_name":"PostToolUse"}' \
  | "C:/Users/sugig/.claude/skills/continuous-learning/hooks/observe-wrapper.sh" post
# exit=0

# Caminho PreToolUse
echo '{"tool_name":"Bash","tool_input":{"command":"ls"},"session_id":"post-fix-verify-pre-001","cwd":"...","hook_event_name":"PreToolUse"}' \
  | "C:/Users/sugig/.claude/skills/continuous-learning/hooks/observe-wrapper.sh" pre
# exit=0
```

O `observations.jsonl` recebeu:

```
{"timestamp":"2026-04-21T05:57:54Z","event":"tool_complete","tool":"Bash","session":"post-fix-verify-001",...}
{"timestamp":"2026-04-21T05:57:55Z","event":"tool_start","tool":"Bash","session":"post-fix-verify-pre-001","input":"{\"command\":\"ls\"}",...}
```

Ambas as fases agora produzem eventos corretamente tipados.

**Observação sobre verificação ao vivo do CLI:** as alterações de configurações entram em vigor na
próxima inicialização de sessão do CLI `claude`. Reinicie o CLI e execute uma chamada da ferramenta Bash para
confirmar que novas linhas aparecem no `observations.jsonl` da sessão real do CLI.
